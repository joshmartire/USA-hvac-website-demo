# HVAC Website Template — USA version

A reusable, production-ready static website for heating and cooling companies, built to the Rank Boss master website specification (technical SEO, local SEO, schema, accessibility, legal drafts). It includes an **instant system estimate**: the visitor picks a furnace, air conditioner, both, a heat pump or a ductless system, their home size and efficiency level, and sees a ballpark installed price based on the client's own prices, plus a **repair-or-replace check**.

Static HTML, CSS and JavaScript. No frameworks, no tracking and no third-party requests at all: fonts are self-hosted, the hero animation is drawn in the browser, and the estimate is calculated in the browser.

American version of the HVAC template: American spelling, °F, USD, `en-US`, Michigan licensing and permit wording (licensed mechanical contractor, mechanical permits, EPA 608), US privacy and terms drafts. Demo: `rankboss-hvac-us.pages.dev` (noindexed). The Canadian version lives in `hvac-website-template`.

```
/assets/img/              logo, favicons, social image (generated by make_images.py)
/_build/                  generator, content and QA — NOT published
  site.config.json        ← client details, colours, services, intro, emergency wording and ESTIMATE PRICING
  content_services.py     ← service page copy + per-city paragraphs
  content_costs.py        ← "what affects the cost" and "questions to ask" per service
  content_cities.py       ← service-area cities: local conditions, permits and licensing
  pages.py                ← home, about, FAQ and legal copy
  build.py                ← generator (header, footer, nav, schema, sitemap, estimate page)
  qa.py                   ← static checks (links, SEO, schema, word counts, contrast…)
  qa_browser.py           ← browser checks (intro, airflow, sequence, estimator maths, axe)
```

**Never hand-edit the generated HTML.** Change `_build/`, then rebuild.

## Setting up a new client

1. Edit `_build/site.config.json`: `province` is the state code (e.g. `MI`), `legal_jurisdiction` the state name, `temps` the hero/no-heat temperatures in °F. Then business name, legal name, domain, phone, email, hours, address (or `null` for a service-area business), Google Business Profile, social profiles.
2. Brand and offer:
   - `services`: delete any slug the client doesn't offer. Its pages, menu and footer links, sitemap entries, form options and estimate options disappear. Fix any sentences listed in `_build/removed-service-mentions.txt` (QA fails while it exists).
   - `accent` (cool colour, used for buttons and highlights) and `heat` (warm colour for heating visuals), both `#rrggbb`. The build stops if either is too dark to read.
   - `logo`: client logo in `assets/img/client/` (transparent PNG best).
   - `photos`: the client's own job photos only (see `_build/photos.py`).
   - `emergency_24_7`: set `true` **only** if the client really answers no-heat calls around the clock. It changes the wording of the no-heat band.
3. **Estimate pricing** (`estimator` block), the client's real numbers:
   - `systems[].base`: typical installed price (USD) for a mid-size home (1,200–2,000 sq ft) at the standard efficiency level, including removal of the old equipment and normal venting/connections. Remove any system the client doesn't install.
   - Ductless: `base` = one zone, `extra_zone` = each extra indoor head, `max_zones`.
   - `home_sizes[].price_mult`, `tiers[].price_mult`, `addons[].price`, `range_pct`, `minimum_job`, `round_to`.
   - `repair_rule.threshold` (age × repair cost rule of thumb, default 5,000) or `enabled: false` to hide the check.
   - `enabled: false` removes the tool, its nav links, hero picker and legal paragraphs.
4. `form_endpoint`: FormSubmit (`https://formsubmit.co/CLIENT-EMAIL`). The first submission sends an activation email that must be confirmed.
5. Cities changed? Rewrite `content_cities.py` and each service's `"cities"` text. Keep it genuinely local.
6. Review everything marked `CLIENT REVIEW` (HTML comments and config notes): hero badges, working standards, about page, emergency availability, legal drafts.
7. Build and test:
   ```bash
   pip install pillow fonttools brotli playwright
   python3 _build/build.py
   python3 _build/qa.py
   python3 _build/qa_browser.py --axe path/to/axe.min.js   # axe optional: npm pack axe-core
   ```
8. At launch: set `"domain"` to the client's domain and `"demo_mode": false` (removes noindex and the yellow demo banner).

## Opening animation

A thermostat dial sweeps from cool to heat while the readout climbs to 70 °F, then the name stamps in and the panels split. It plays on **whichever page a visitor opens first** in a browser session (home page or a service page from Google), then never replays that visit. It's skipped for a `#hash`, for reduced-motion users and on the 404 and thank-you pages, and a tap or key press skips it. Headlines are in the HTML underneath from the first paint, so it never hides content from Google. `"intro_scope": "home"` limits it to the home page; `"intro": false` turns it off.

## How the instant estimate works

`base price × home-size multiplier × efficiency multiplier + add-ons` → ± `range_pct`, rounded, never below `minimum_job`. Ductless is priced per zone instead of by home size, and duct-based add-ons are hidden for it. Everything runs in the browser; nothing is sent until the visitor submits the lead form, which carries the system, size, efficiency, zones, add-ons, the range shown and (optionally) the age of their current system. The home page's system picker is a plain form, so it works without JavaScript and deep-links (`/system-estimate/?system=heat-pump`).

## Design and motion

- Palette: deep blue-black with a cool/heat dual tone (both colours from config). Anton headlines, Barlow body, JetBrains Mono for readouts.
- Hero: canvas airflow streamlines that warm from cool to heat across the screen and bend around the cursor. Paused off screen and in background tabs, one still frame for reduced motion, fewer particles on phones.
- Pinned "inside the system": return & filter → blower → burners & heat exchanger → cooling coil → supply ducts build in as you scroll, with moving airflow, a spinning blower and flickering burners.
- Estimate teaser gauge, no-heat band with frost and snow, velocity marquee, scroll-fill statement, card spotlights.
- Everything respects `prefers-reduced-motion` and works without JavaScript (the estimate shows a call/contact fallback).

## Deploying

Cloudflare Pages (like the other Rank Boss demos): connect the repo, no build command, output directory `/`. `_headers` noindexes the `*.pages.dev` hostname only. For GitHub Pages: Settings → Pages → `main` / root; the build writes `CNAME` once a real domain is set.

## Adding a page later

- New service: add an entry to `content_services.py` (with its three `cities` paragraphs), a `COSTS` and `ASK` entry in `content_costs.py`, add the slug to `services` in the config, rebuild, run QA. Menus, footer, sitemap, schema and city pages update automatically.
- New city: add an entry to `content_cities.py` and a paragraph for it in every service's `cities`, rebuild, run QA.
